# 论文方法流程图

把方法画成读者可以沿箭头理解的科学过程。先读 [视觉标准](references/approved-standard.md)，按需读 [制作与交付](references/production-workflow.md)。这些是作者认可成品提炼的默认偏好，用户当前要求与最新手改成品优先。

先查看用户最新成品。本地若存在 `assets/approved-reference.png`、`.pptx`，它们是经过用户强化箭头的 DFQI 参考；否则查看随包的 `assets/demo/method-demo.png`。参考决定视觉语法，当前论文与代码决定科学内容。模块数量、DFQI 判据、特定参数和实验名称不能直接套用于其他研究。

## 内容先于绘制

从作者材料提取输入对象、候选表示、质量评价、选择/停止、输出和独立对照。用简短内容契约记录每个模块“接收什么 → 执行什么 → 产生什么”，标明数据传递、推进、反馈和条件分支。每个图形都指向一个科学对象，每根箭头都有明确含义。

主流程默认左到右，模块内部上到下。先分配宽度、子区、对齐线和连线走廊。主模块用有语义的彩色虚线边框和浅色标题带，内部功能子区用细灰框与短标题。宽度跟随内容，不机械等宽；需要其他方向时按因果顺序重新布局。

以波形、频谱、矩阵、张量、模态族、候选网格等抽象科学图形解释功能。文字保留板块名、变量和必要注释。数值插图约占表达内容的一小部分，参考偏好约 20%；这是内容分工，不能把栅格图片面积误当比例。插图从已有数据或明确标注的示例代码生成，不把流程变成诊断曲线的堆砌。

## 制作与检查

默认 PowerPoint 原生对象为可编辑主源，同一功能内对象分组。可用 `scripts/build_method_demo.cjs` 学习框架与科学图形实现，再按当前方法重写；其中示意数据不是实验结果。默认 Times New Roman，数学变量斜体，帽子按字形视觉中心对齐。不要直接用组合字符假定数学排版正确。

主流程与内部推进用清晰的黑色实心箭头；独立对照/反馈用橙色并说明语义。优先复制最新认可 PPT 的箭头属性。检查实际方向、端点与最终打印尺寸，不能只凭 XML 的 headEnd/tailEnd 名称判断方向。箭头走预留走廊，避免穿过内容。

颜色区分模块或对象，颜色、线型、矩阵数值必须有短而邻近的图例。零值、空白、不可行、未评估分别表达；矩阵零值使用可见浅底和边线。曲线同时使用不同颜色与线型，图例小于板块标题。综合流程图默认不用某一次实验的编号、初始点数量或下一步参数值。

导出后检查 PDF 全图、箭头/公式局部与目标印刷尺寸。检查流程是否一眼可追踪、图例是否可读、文字是否遮挡及模块间距是否过大。文字拥挤时先调整结构，不通过不断缩字号解决。

## 导出与论文集成

交付 PPTX、PDF、PNG 和简短来源记录。Windows 已有 PowerPoint 时用 `scripts/export_ppt_pdf.ps1` 从最新 PPT 原生导出 PDF 与预览，不修改源文件。SVG 仅在需要时生成，并核对与最新成品一致。不能用旧 SVG 或旧脚本覆盖用户手改 PPT。

只有任务要求论文集成时，查 tex 实际引用路径、备份图与 ZIP，再替换同名图件。验证 PDF 与 ZIP 条目一致、其他条目没有意外变化，保留 provenance。涉及图注变化时按当前授权范围更新。修改 tex 后用当前环境要求的编译工具检查；未编译就说明验证范围。
