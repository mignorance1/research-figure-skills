# 同步与交付

## 建立当前版本记录

登记原始评论、工作源、认可图件、最终导出和 response。对关键文件可保存路径、SHA-256、源图与导出时间，以及稿件和回复中的对应标识。哈希用于识别具体版本；图件语义与文字解释仍需人工核对。

作者指定最新文件后，从该文件或其实际工作源继续。保留前一版，避免覆盖唯一的可恢复版本。交付记录写明当前有效的最终路径。

## 避免素材已改、成品仍旧

对方法图或实验图更新，依次核对：

1. 最新认可的源图及其导出。
2. 论文源文件中实际引用的路径。
3. response 实际嵌入的媒体，或生成器使用的图件清单。
4. 最终论文和 response 页面中的图形。

只有最终页面展示了新图才算替换完成。可以对 Word 媒体文件校验源 PNG 哈希；有缩放、转换或重绘时记录来源并用页面检查确认。PDF 导出常重写对象，源文件哈希与最终文件哈希分别记录。

## 删除实验或修改表图

删除实验时，检索并核对其正文、图题、摘要和结论中的相关主张，以及 response 中的总结、复现图、实验规模和计算成本。按实际依赖调整编号、引用和统计总量。同一数据集还用于保留实验时，保留相应材料。

修改表格时同时检查标题、列名、缩写、单位、箭头、粗体、显著性和脚注。作者取消部分粗体时，删除相应说明，或明确说明只适用于保留的列与区域。对照方向和比较范围由当前实验设计确定。

数学定义变化时检查摘要、贡献、流程图、算法、公式解释、消融列名、图表说明和回复摘录。清除已经撤回的指标、方法名称与结论的残留描述。

## 页码与行号

先编译或导出论文，再确认图表、章节和参考文献位置。页码来自实际 PDF。需要行号时，使用同版稿件的行号副本，并解释行号是全文连续、逐页还是逐栏重置。

排版变化后，旧行号会指向不同文字。更新定位时匹配原来的文字内容或稳定标识，再检查新范围内确有相关修改。只验证行号存在不足以确认对应关系。

同一页可能同时存在方法叙述、表格与其他段落。保留有用的章节、图表和公式编号，使定位在小幅重排后仍清楚。response 自有页码与手稿页码明确区分。

## 最终导出

使用当前环境可用的文档或 LaTeX 工具。沿用原模板和作者认可的排版。干净版与标红版的文字、数据和图件内容对应一致；不同标记约定引起的呈现差异按其要求检查。

Windows 安装有 Word 时，助手可执行：

```powershell
powershell -NoProfile -File scripts/export_word_pdf.ps1 -Source "response.docx" -Destination "qa/response.pdf"
```

脚本只读打开源文件并校验源哈希，输出 PDF 和 `.export.json` 记录。它只关闭自己打开的文档，检测到已有 Word 进程时保留其会话。其他系统使用环境中可用的渲染工具。

检查导出的所有页面，尤其是新增图、公式、跨页表格、图题与位置段落。局部修改时，可先识别变化页面；未变页面只有在已检查且渲染结果确实相同时才沿用原检查。

## 交付前核对

- 原始评论完整，每个实质要求都有对应答复。
- 结果、单位、比较方向、置信区间与引用来自当前材料。
- 关键图表与公式有解释，图例与表注对应实际内容。
- 颜色、下划线、粗体的开头说明与实际格式一致。
- 论文和 response 都使用最新认可图件，撤回内容已经同步处理。
- 页码和行号对应最终文件；没有占位符、未解析引用、截断或重叠。
- 仅交付用户要求的文件；保存本轮源文件、版本记录和必要检查记录。

## 公开为 skill

公开说明、匿名骨架和原创工具。作者模板、未发表论文、原始审稿意见、实验数值、患者材料和含本机路径的记录留在本地。只上传经本轮授权的仓库文件，提交前核对暂存清单；本地参考放在忽略路径中。
